Integration architecture: ServiceNow ↔ Jira without paid middleware

  • Integration design
  • Native REST
  • Cost vs. control
Context
Three ways to connect ServiceNow and Jira: the out-of-box Jira spoke, which requires a paid Integration Hub package; Azure Automation as middleware, the common choice on the market but slow to respond; or native REST.
Design decision
Chose native REST: a direct point-to-point integration with no extra licence and no middleware layer, owned and versioned inside the platform.
Outcome
Faster responses than the Azure Automation route, no Integration Hub licence cost, and full control over mappings and logic. A pattern that suits organisations that want to keep platform spend down.

Access request design: nine reporting roles, one catalog item, one flow

  • Catalog design
  • Flow Designer
  • Identity provisioning
Context
Nine financial reporting access options, each needing approval and then the right Active Directory and Microsoft 365 group membership.
Design decision
One catalog item and one Flow Designer workflow for all nine options instead of nine separate items, with approval first and provisioning to Active Directory and Microsoft 365 groups only after approval.
Outcome
Fewer catalog objects to maintain, one consistent approval path, and access granted automatically, with no manual group changes.

Employee Center: evolving the portal without breaking it

  • Employee Center
  • UX consistency
  • Release governance
Context
Enhance the employee portal for any device and make it consistent to use, while the existing portal stayed in production.
Design decision
Responsive navigation, a reusable custom ticket survey widget, and one consistent pattern for approval and ticket actions across the portal, built to stay compatible with the existing portal.
Outcome
Key changes validated in DEV before release, and full compatibility with the existing portal kept throughout.
